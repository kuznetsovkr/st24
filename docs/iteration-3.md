# Итерация 3: подготовка эксплуатации

Состояние на 17 октября 2026 года: реализация завершена локально, production
не обновлялся. Первая итерация добавила внешний мониторинг, вторая — надёжную
очередь Telegram и контроль оплаты. Третья готовит их безопасный запуск.

## Что подготовлено

- Общая проверка конфигурации backend и monitor до запуска процесса, включая
  production-ограничения и поддерживаемую версию Node.js.
- Контролируемая production-сборка frontend из отдельного файла публичных
  настроек, без подмешивания локального `.env`.
- systemd-сервисы API и независимого monitor, таймеры, каталоги состояния,
  ограничение прав, ротация логов и последовательный запуск check/summary.
- Корректное завершение HTTP, очереди Telegram, polling, Redis и PostgreSQL
  при перезапуске; остановка ограничена сроком меньше systemd TimeoutStopSec.
- Деплой с блокировкой, fast-forward, тестами, backup БД, пробным восстановлением
  и двукратной инициализацией схемы под application-role.
- Сохранение и откат прежних API unit/tmpfiles/logrotate вместе с кодом.
  Схема БД автоматически назад не откатывается.
- Проверка нового API напрямую и через публичный URL: здоровые зависимости,
  свежий timestamp, запрет кэширования и одинаковый идентификатор процесса.
- CI на Linux с PostgreSQL, проверкой systemd, shell и зависимостей; Dependabot.
- Обновление уязвимых зависимостей. Старый `ts-node-dev` заменён встроенным
  `node --watch` с тем же TypeScript-загрузчиком.

## Что проверено локально

Node.js 24.21.0, Windows:

- 169 тестов: backend 97, monitor 58, frontend config 7, deploy tools 7.
- Production-сборка frontend на синтетических публичных настройках.
- Проверка структуры systemd-пакета, Bash-сценарии отката, ShellCheck.
- Изолированная PostgreSQL 18.4: пустая схема, повторная инициализация,
  резерв/освобождение/списание остатков, paid → outbox и Telegram cursor под
  ролью без superuser. Временный кластер после проверки остановлен;
  вспомогательные файлы перенесены из репозитория в системный Temp.
- Линтеры без ошибок; остаются 8 прежних предупреждений React.
- Полный `npm audit`: 0 известных уязвимостей на дату проверки.

Запуск реального systemd и полного backup/restore smoke на Linux в этом
продолжении не выполнялся. Эти проверки включены в `.github/workflows/ci.yml`
и должны пройти после публикации коммита, перед production-выкатом. Локальный
PostgreSQL-прогон использовал `--schema-only`; CI запускает полный вариант и
проверяет восстановленные строки до повторной инициализации схемы.

## Следующий этап

Зафиксировать изменения и получить зелёный Linux CI. Затем пройти
[production runbook](../ops/README.md): сначала staging и пробный откат, затем
API на существующем сервере и monitor на отдельном независимом хосте. Вторую
копию сайта или PostgreSQL для monitor разворачивать не требуется.

Первый rollout выполняется новым guarded-скриптом, без предварительного запуска
API новой версии. Реальные `/etc`-конфиги, backup/retention, секреты и независимый
канал алертов настраиваются на соответствующих серверах по runbook.
